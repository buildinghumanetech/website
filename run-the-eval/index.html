Path one

Gate your pull requests

The Humane Gate reads every pull request against the eight principles and posts one advisory verdict. It blocks nothing. It runs in your CI on your own Anthropic key, and nothing is sent to us.

  1. Add your key

    Add ANTHROPIC_API_KEY as a repository secret, under Settings → Secrets and variables → Actions. The judge runs on your key, in your runner.

  2. Add the workflow

    Save this as .github/workflows/humane-gate.yml. That is the whole install.

    name: humane-gate

on:
  pull_request:
    types: [opened, synchronize, reopened]
  # A person replying "/humane accept" is the only conversation CI can have.
  issue_comment:
    types: [created]

permissions:
  contents: read
  pull-requests: write
  checks: write

jobs:
  advisory:
    runs-on: ubuntu-latest
    if: >-
      github.event_name != 'issue_comment' ||
      (github.event.issue.pull_request != null &&
       contains(github.event.comment.body, '/humane accept'))
    steps:
      # Check out the DEFAULT branch, never the pull request. This is what
      # keeps a pull request from supplying the policy it is scored against.
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event.repository.default_branch }}
          fetch-depth: 0

      - uses: buildinghumanetech/humane-gate-action@v1
        with:
          anthropic-api-key: ${{ secrets.ANTHROPIC_API_KEY }}

  3. Open a pull request

    The verdict appears as a comment, plus a neutral check named humanebench / advisory. Disagree with a finding? Reply /humane accept <id> <reason> and the decision goes on the record under your name.

About $0.07 per pull request on your key, measured across our nine demo PRs. Verdicts can vary between runs on the same diff. Full documentation is in the humane-gate-action README.

Path two

Score your product on real conversations

The HumaneBench CLI judges real transcripts against the eight principles and writes a local HTML report. One binary. Your transcripts stay on your machine until you say otherwise.

  1. Install Rust

    Skip this if cargo --version already works.

    curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

  2. Build the CLI

    git clone https://github.com/buildinghumanetech/humanebench.git
cd humanebench/cli
cargo build --release
alias humanebench="$PWD/target/release/humanebench"

  3. Bring your conversations

    Claude Code and Codex logs are found automatically. For your own product, export conversations as JSONL in the documented schema and pipe them in.

    # agent logs on this machine
humanebench ingest

# your product: see the contract, then pipe your export
humanebench schema
your-export | humanebench ingest --stdin --source normalized

  4. Price it before you pay

    A dry run shows the call count and token estimate. No key needed, nothing spent.

    humanebench score --provider openrouter --dry-run

  5. Score

    Get a key at openrouter.ai/keys. The first run names exactly what leaves your machine and asks for consent.

    export OPENROUTER_API_KEY=your_key_here
humanebench score --provider openrouter

  6. Read the report

    Rendering is free and never re-judges. --share drops verbatim excerpts so you can pass it around.

    humanebench report --out report.html
humanebench report --share --out share.html

Read it right. The CLI uses one judge model. The published leaderboard uses an ensemble and scores each prompt on the one principle it was built to test. Same rubric, different statistic. Do not put a CLI score next to a leaderboard score.

Path three

Benchmark a model

The research harness runs the benchmark prompts against any model on OpenRouter, in three conditions: no system prompt, a humane persona, and an adversarial one. It runs on Inspect.

  1. Set up

    git clone https://github.com/buildinghumanetech/humanebench.git
cd humanebench
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

  2. Add your key

    cp .env.example .env
# open .env and set OPENROUTER_API_KEY

  3. Smoke test

    Twenty-four prompts. Confirms everything is wired before you spend real money.

    inspect eval src/test_task.py --model openrouter/openai/gpt-5

  4. Full run

    Swap in any model as openrouter/<provider>/<model>. Inspect wants an empty logs/ folder, so move old runs first.

    inspect eval src/baseline_task.py src/good_persona_task.py src/bad_persona_task.py \
  --model openrouter/openai/gpt-5

  5. Read the results

    inspect view

Full docs, rubrics and the dataset live in the repo.
